# DSH 企业客户端插件（dsh-enterprise）· 核心文档

> 双面插件:`lib/index.js`(Node 端,宿主进程内运行)+ `lib/client.js`(浏览器端,注入 Web UI) · 配套文档:《DSH 企业网关 · 核心文档》 · AI 助手修改代码前须先阅读 [AGENTS.md](../AGENTS.md)

---

## 1. 概述

本插件安装于 DSH(Desktop/Web)终端,提供企业统一的登录与终端治理能力:

1. **强制登录**:未登录企业账号时呈现全屏遮罩,不可跳过;登录成功后网关签发的 JWT 写入 DSH 凭据库
2. **模型配置托管**:登录时将网关下发的企业模型写入 DSH provider 配置,并隐藏原生「模型」设置页(防止绕过与误配置),卸载插件后恢复
3. **心跳保活**:定时向网关上报在线状态与设备信息;随心跳执行**令牌滑动续期**(持续使用期间令牌不过期)与**模型配置自动修复**(网关模型变更时自动重写本地 provider)
4. **登出即清场**:清除全部模型配置并锁定页面,须重新登录方可继续使用
5. **插件管控(自动清理)**:网关 `allowedPlugins` 非空即启用——清单外插件于客户端**启动 4 秒后**及**每次心跳收到违规判定时**被自动清理:从 profile `package.json` 的 bundles/dependencies 中移除(权威,重启后不再加载),并尽力删除 `node_modules` 实体(被占用时记入重试队列,随每拍心跳重试直至删除完成)。保护名单 `dsh-enterprise` / `@deepseek-ai/dsh-base` / `@deepseek-ai/dsh-web-app` 永不清理;清单为空表示不限制
6. **生效时机**:清理移除的是"下次启动不再加载";**当前 DSH 会话内已加载的 bundle 无法卸载**(Node ESM 无运行时卸载机制)。用户端插件管理页在清理发生后显示"重启 DSH 后完全退出"横幅,仅本次进程存活期内显示,重启后自动消失

## 2. 架构与文件结构

```
dsh-enterprise/
├── package.json          # DSH 插件清单(cordis 插件规范)+ build/test/check 脚本
├── cordis.patch.yml      # profile 级服务补丁(settings 路径重定向)
├── build.mjs             # 零依赖构建:src-node 复制 + src-client 拼接 → lib/(含产物自检)
├── src-node/             # Node 半区源码(ESM)
│   ├── index.js          # 入口:apply 装配(路由注册/心跳/占位密钥/启动对账/规则钩子)
│   ├── shared/           # paths(全部落盘路径唯一定义处)/ fs-utils(原子写)/ log / version
│   ├── state/            # enterprise-state.json 读写(含旧版状态文件迁移)
│   ├── settings/         # yaml-edit(主 settings.yaml 行级改写)/ provider-config(provider 与凭证写入)
│   ├── auth/             # login(登录自动配置 + 模态白名单)/ logout(清场)
│   ├── device/           # 设备信息采集 + 本机插件清单(供管控比对)
│   ├── heartbeat/        # 心跳:增量上报 / 令牌续期 / modelFingerprint 联动
│   ├── enforce/          # 插件管控强制执行:清理允许清单外插件
│   ├── policy/           # /policy/current 拉取、缓存与版本回执;企业插件源;市场元数据
│   ├── rules/            # 规则引擎(block-url/block-word/高危命令,纯函数)/ 宿主钩子
│   └── web/              # loopback 适配器 / 17 条路由 / 独立登录页
├── src-client/           # 浏览器半区源码(按文件名前缀排序拼接:10- 工具 … 95- 横幅 99- 入口)
├── test/                 # node --test 单元测试:YAML 三态/幂等、规则引擎、模态白名单等 37 项
└── lib/                  # ⚠ 构建产物(即安装内容),手工修改将在下次构建时被覆盖
```

两个半区通过状态文件与网关 API 协作:Node 半区承担全部落盘操作与网关通信,浏览器半区仅负责 UI(遮罩/面板/水印/横幅)。

## 3. 核心机制

### 3.1 settings 路径解析(关键)

```
dshSettingsFile() = ENT_SETTINGS_PATH 环境变量 ?? dshHome()/settings.yaml
```

- 实例 profile 通过 `cordis.patch.yml` 将 settings 服务指向独立文件;插件写入 provider 时**必须**跟随同一文件
- 未携带该环境变量启动实例时,插件将读写共享的 `~/.dsh/settings.yaml`,进而污染生产 Desktop 配置——此为最主要的运营事故来源

### 3.2 登录配置写入(loginAndConfigure)

1. 调用网关 `/auth/login` 换取 JWT,写入 DSH 凭据库
2. 将网关企业模型写入 DSH provider(模型列表先行拉取并缓存至 `enterprise-state.json` 快照)
3. **屏蔽官方 deepseek 泄漏**:settings.yaml 必须包含 `llm-deepseek: models: []`,登录与登出两条路径均须保证;缺失时 DSH 内置官方 deepseek 模型将出现在用户选择器中
4. **provider 段校验红线**(违反将导致企业模型全部消失且无显式报错):模型 `input` 仅允许 `text`/`image`;`reasoningEfforts` 必须为 dict 格式,纯非思考模型应省略该字段
5. 登出(清场):providers 置空、移除默认模型、保留官方模型屏蔽段(采用精确正则,幂等实现,三种状态均有单元测试覆盖)

### 3.3 心跳(runHeartbeatOnce)

- 定时 POST `/heartbeat`;设备信息采用**增量上报**(diff 检测,仅变化时发送)
- **modelFingerprint 联动**:网关返回企业模型 id 列表指纹,与本地值比对;发生变化时使用已存令牌无密码重写 provider 配置,实现网关模型变更后终端自动跟随
- **配置热生效**:网关地址每拍重读状态文件,更换网关或修改地址后最迟下一个心跳周期自动切换,无需重启实例;心跳开关与间隔经文件监听秒级热重载(每拍 tick 的配置指纹比对作为兜底)
- **停用自动清场**:心跳连续 2 次 HTTP 401(对应账号被网关停用/凭证被吊销/密码变更;单次抖动与网络错误不触发)→ 执行本地清场 → 客户端轮询发现 `configured=false` 后立即呈现全屏登录页,被停用终端最迟约 1 分钟回到登录页

### 3.4 令牌滑动续期

令牌持续使用期间不过期;账号停用后立即失效(网关侧实时校验 enabled 状态)。

### 3.5 状态持久化

`~/.dsh/enterprise/enterprise-state.json` 存储账号、模型快照、指纹与设备信息。全部写入经由原子写(临时文件 + rename)完成,防止中途损坏。

## 4. 浏览器端(client.js)

- **登录遮罩**:未登录时全屏覆盖,无跳过按钮;支持**热挂载**——每 30 秒轮询状态,`configured` 变为 false 时立即呈现遮罩(对应心跳 401 自动清场或管理员停用账号)
- **企业面板**:仅显示状态/登录账号/网关地址/心跳,不显示具体模型名(安全要求:用户端不暴露上游模型)
- **隐藏「模型」设置页**:MutationObserver 持续扫描,安装即隐藏,卸载后恢复
- 模型多模态徽章:图片/视频/音频/纯文本
- 双语 i18n:`useT2()`(React 组件)/`t2()`(非 React),跟随宿主 `<html lang>`

## 5. 插件管理 API

| 路径 | 说明 |
| --- | --- |
| `POST /api/enterprise/login` | 登录(server/username/password)并写入配置 |
| `GET /api/enterprise/status` | 状态查询(账号/心跳/续期) |
| `POST /api/enterprise/logout` | 清场登出 |
| `GET /api/enterprise/usage?days=` | 用量视图(透传网关计费) |

## 6. 运维与排错速查

| 现象 | 排查方向 |
| --- | --- |
| 登录成功但模型选择器无企业模型 | `settings/describe` 是否存在 provider ns → 校验红线(input 白名单/reasoningEfforts dict) |
| 模型间歇性消失 | 心跳 modelFingerprint 是否触发自动修复;状态文件中的快照 |
| 官方 deepseek 混入列表 | settings.yaml 屏蔽段(登录与登出两条路径均需检查) |
| 测试实例更新插件后无变化 | 未执行 remove+add 重装(file: 安装为复制而非引用) |
| 心跳 401 | JWT 过期或被清除;检查续期逻辑与凭据库 |
| 插件写入错误的 settings 文件 | ENT_SETTINGS_PATH 与 profile 的 cordis.patch.yml 指向是否一致 |

## 6.5 新版 DSH 兼容性（0.1.7+）

- 新版 DSH 会把旧 `settings.yaml` 导入当前 profile 的 `cordis.patch.yml` 并改名；插件登录/修复会同时写：
  - 旧路径：`settings.yaml` + `enterprise-settings.yaml`
  - 新路径：profile `cordis.patch.yml` 的 `llm-pi-ai` / `agent-default-model` / `llm-deepseek` 行
- 已检测到 `settings.yaml.imported` 时，插件只走 profile patch 路径，避免重复导入
- 双协议并存：`llm-pi-ai.providers` 同时写 `ent-gateway`（`openai-completions`，默认）与 `ent-gateway-responses`（`openai-responses`），后者走网关 `/v1/responses`（Codex 方言）；两个 provider 同模型同凭证（`ENT_GATEWAY_TOKEN_V2`），登出一起清理；`agent-default-model` 默认仍指向 `ent-gateway`
- 插件包新增 `locale/en.json`、`locale/zh.json`、`icon` 与 `dsh.manifestVersion: 1`，供新版插件管理页显示中文名与图标

## 7. 版本与发版

- 版本号需同时修改 `package.json` 与 `src-node/shared/version.js`
- 发版流程:`npm version patch` → `git push --follow-tags` → GitHub Actions 自动执行 构建 → 测试 → npm publish → Release
