# DSH 企业客户端插件（dsh-enterprise）· 核心文档

> 版本 2026-09-11 · 双面插件：`lib/index.js`（Node 端，跑在 DSH 宿主进程）+ `lib/client.js`（浏览器端，注入 Web UI）
> 配套文档：《DSH 企业网关 · 核心文档》
>
> **v0.6.0 改名**：插件由 `dsh-ent-login` 更名为 `dsh-enterprise`（彻底改：API 路径 `/api/ent-login/*` → `/api/enterprise/*`、登录页 `/plugins/ent-login` → `/plugins/enterprise`、状态文件 → `enterprise-state.json`）。
> 升级注意：① 状态文件自动迁移（老文件保留沿用）；② **网关策略的插件允许清单要把 `dsh-ent-login` 换成 `dsh-enterprise`**（客户端对自身有保护兜底，漏配不会被误清，但会持续告警）；③ 老版本安装的机器用卸载脚本移除旧包名（脚本已兼容新旧两名）。
>
> **插件管控（自动清理）**：网关 `allowedPlugins` 非空即启用——清单外插件在客户端**启动 4s 后**与**每次心跳收到违规判定时**自动清理：从 profile `package.json` 的 `dsh.profile.bundles`/`dependencies` 移除（权威，重启后不再加载）+ 尽力删除 `node_modules` 实体（运行中被占用则记入重试队列，每拍心跳自动重试直到删净）。保护名单 `dsh-enterprise` / `@deepseek-ai/dsh-base` / `@deepseek-ai/dsh-web-app` 永不清理（客户端过滤，网关清单漏配不会触发每拍空转）；清单为空 = 不限制。冒烟测试：`node test-enforce.mjs`（假网关 + 假 profile 端到端验证）。
>
> **生效时机**：清理移除的是"下次启动不再加载"，**当前 DSH 会话内已加载的 bundle 无法卸载**（Node ESM 无运行时卸载机制）——员工端插件管理页会在清理发生后显示"重启 DSH 后完全退出"横幅（`lastPluginCleanup`，仅本次进程存活期内显示，重启后自动消失）。

## 1. 它是什么

装进 DSH（Desktop/Web）的企业登录与管理插件。安装后：

1. **强制登录**：未登录企业账号时全屏遮罩，不可跳过；登录后网关 JWT 写入 DSH 凭据库
2. **自动接管模型配置**：登录时把网关的企业模型写入 DSH 的 provider 配置；**隐藏原生「模型」设置页**（防绕过/防误配），卸载插件才恢复
3. **心跳保活**：定时向网关上报在线状态 + 设备信息；跟随心跳做**令牌滑动续期**（活跃使用永不过期）和**模型配置自动修复**（网关模型变更时自动重写本地 provider）
4. **登出即清场**：清除全部模型配置 + 锁页面，必须重新登录

## 2. 文件结构（v0.5.0 起工程化拆分）

```
dsh-enterprise/
├── package.json          # DSH 插件清单（cordis 插件规范）+ build/test/check 脚本
├── cordis.patch.yml      # profile 级服务补丁（settings 路径重定向）
├── build.mjs             # 零依赖构建：src-node 复制 + src-client 拼接 → lib/（产物自检）
├── src-node/             # Node 半区源码（ESM）—— ⚠ 改这里，别改 lib/
│   ├── index.js          # 入口：apply 装配（路由注册/心跳/占位 key/启动对账/规则钩子）
│   ├── shared/           # paths（所有落盘路径唯一出处）/ fs-utils（原子写）/ log（client-log.txt）/ version
│   ├── state/            # enterprise-state.json 读写（含 v0.5.x 老状态文件迁移）+ ENT_GATEWAY_TOKEN 读取
│   ├── settings/         # yaml-edit（主 settings.yaml 行级改写，单测覆盖）/ provider-config（provider+凭证写入）
│   ├── auth/             # login（登录自动配置 + mapGatewayModels 模态白名单 + repairConfigure）
│   ├── device/           # 设备信息采集 + 本机插件清单（管控比对；清理后 resetDeviceInfoCache）
│   ├── heartbeat/        # 心跳：增量上报 / 令牌续期 / modelFingerprint 联动
│   ├── enforce/          # 插件管控强制执行：启动/心跳自动清理允许清单外插件（保护名单兜底）

│   └── web/              # respond（loopback 适配器）/ routes（17 条：16 条 /api/enterprise/* + /plugins/enterprise 登录页 / login-page
├── src-client/           # 浏览器半区源码（按文件名前缀排序拼接：10- 工具 … 80-97 各面板 99-入口）
├── test/                 # node --test 单测：YAML 三态/幂等、规则引擎、模型模态白名单
└── lib/                  # ⚠ 构建产物（安装的就是它），手改会被下次 build 覆盖
    ├── index.js          # Node 端入口
    └── client.js         # 浏览器端（__ModuleLoader__ 单文件，由 src-client 拼接生成）
```

**开发流程（改代码必走）**：

```powershell
# 1. 改 src-node/ 或 src-client/
# 2. 构建 + 单测（~3 秒，零 npm 依赖）
pnpm --filter dsh-enterprise check      # = node build.mjs && node --test "test/*.test.mjs"
# 3. 重装到测试实例（file: 是复制不是引用，必须 remove+add）
dsh.cmd plugin --profile <测试profile> remove dsh-enterprise
dsh.cmd plugin --profile <测试profile> add "file:<插件构建目录>"
# 4. 重启实例（测试实例启动脚本 已带 ENT_SETTINGS_PATH）
cmd /c "<终端启动脚本>"
```

工程化约定：

- `lib/` 全部是构建产物；直接改 lib 的代码会在下次构建时丢失
- src-client 拼接顺序 = 文件名字典序（数字前缀控制）；各片段共享同一工厂作用域，与拆分前的单文件完全等价
- 共享的可变状态各归其主：心跳状态在 `heartbeat/`、策略缓存在 `policy/`、规则计数在 `rules/engine`，跨模块一律走取值函数（如 `currentHeartbeatState()`、`peekCachedPolicy()`）
- 改 `settings/yaml-edit.js` 前先看 `test/yaml-edit.test.mjs`——历史事故重灾区有回归保护了

## 3. 核心机制（index.js）

### 3.1 settings 路径解析（重中之重）

```js
dshSettingsFile() = process.env.ENT_SETTINGS_PATH ?? join(dshHome(), 'settings.yaml')
```

- 实例 profile 用 `cordis.patch.yml` 把 settings 服务指向独立文件（如 `profiles\<profile>\`），插件写 provider **必须**跟随 `ENT_SETTINGS_PATH` 指向同一文件
- **不带此环境变量启动实例 → 插件读写共享的 `~/.dsh/settings.yaml` → 污染生产 Desktop 配置**（最大运营事故源）

### 3.2 登录写配置（loginAndConfigure）

1. 网关 `/auth/login` 换 JWT → `writeCredential` 写入 `.credentials.yaml`（`ENT_GATEWAY_TOKEN`）
2. `writeProviderConfig`/`syncMainSettingsProvider` 把网关企业模型写成 DSH provider：
   - provider 段 `llm-pi-ai` 下 `providers: {ent-gateway: {...}}`
   - **用 state 存的模型快照**（`GET /v1/models` 拉取后缓存到 `enterprise-state.json`）
3. **屏蔽官方 deepseek 泄漏**：settings.yaml 必须含 `llm-deepseek:\n  models: []`（登录**和**登出路径都要保证）——不加的话 DSH 内置官方 deepseek 模型会出现在员工选择器里
4. **llm-pi-ai 段校验红线**（违反 → 整个 ns 不注册 → 企业模型全部消失，且无显式报错）：
   - 模型 `input` 只能 `text`/`image`（DSH 白名单；网关 `input_modes` 透传前过滤 video/audio）
   - `reasoningEfforts` 必须是 **dict** 格式（`off: none`、`low: low`…），不能是列表；纯非思考模型**省略该字段**
   - 症状识别：`settings/describe` 的 namespaces 缺 `llm-pi-ai`；`session/modelCatalog` groups 为空
5. 登出（清场）：providers 置空 `{}` + 移除 `agent-default-model` + 保留 llm-deepseek 屏蔽段；登出 regex 曾因重复插入 `providers:` 键损坏 YAML——现用精确正则（幂等，三种状态单测过）

### 3.3 心跳（runHeartbeatOnce + syncHeartbeatTimer）

- 定时 POST `/heartbeat`（Bearer JWT）；device 信息**增量上报**（diff 检测，变化才发；网关 `deviceAccepted=false` 时下次强制全量）
- **modelFingerprint 联动**：网关返回企业模型 id 列表指纹，与本地 `lastModelFingerprint` 比对——变化则触发 `repairConfigure()`（用已存 token 无密码重写 provider 配置）→ 网关改模型，终端自动跟随
- 首次心跳只记基线不触发修复
- **状态热生效（v0.7.1）**：网关地址每拍重读 `enterprise-state.json`——换网关/管理员改网关地址，最迟下一个心跳周期自动切换，**无需重启实例**；心跳开关/间隔经状态文件目录监听秒级热重载（watcher 仅是加速器，每拍 tick 的配置指纹比对兜底，watcher 失效最迟下拍也生效）；未登录（无 gateway）时静默跳过该拍
- **停用自动清场（v0.8.0）**：心跳连续 2 次 HTTP 401（账号被网关停用/凭证被吊销/改密；单次抖动与网络错误不清场）→ 自动执行本地清场（`auth/logout.js` 的 `logoutLocal`，与 `/api/enterprise/logout` 共用同一实现：清 provider/凭证/登录态，保留网关地址）→ 客户端登录遮罩轮询发现 `configured=false` 即弹出全屏登录页锁定操作，被停用终端最迟约 1 分钟回到登录页；清场后心跳因 user 已清自动跳过，不会重复清场

### 3.4 令牌滑动续期（refreshTokenIfNeeded）

活跃使用则 JWT 永不过期；停用账号即时失效（网关侧 JWT 实时校验 enabled）。

### 3.5 状态持久化

`~/.dsh/enterprise/enterprise-state.json`：账号、模型快照、指纹、设备信息。所有写入走 `writeTextAtomic`（临时文件 + rename，防中途损坏）。

## 4. 浏览器端（client.js）

- **登录遮罩**：未登录全屏覆盖，无跳过按钮；登录成功 reload；登出按钮 600ms 后 reload；**热挂载（v0.8.0）**——入口每 30s 轮询 `/api/enterprise/status`，`configured` 变 false（心跳 401 自动清场/管理员停用账号）立即挂出遮罩，已挂出则不重复
- **企业面板**：只显示 状态/登录账号/网关地址/心跳 —— **不显示具体模型名**（安全要求：员工端不暴露上游模型）
- **隐藏「模型」设置页**：MutationObserver 持续扫描，nav 中带"模型"标签的按钮 `display:none`，无条件隐藏（安装即隐藏，卸载才恢复）
- 模型多模态徽章：`input_modes` → 图片/视频/音频/纯文本徽章

## 5. 插件管理 API（index.js 注册到宿主）

| 路径 | 作用 |
| --- | --- |
| `POST /api/enterprise/login` | 登录（server/username/password）→ 写配置 |
| `GET /api/enterprise/status` | 状态（账号/心跳/续期） |
| `POST /api/enterprise/logout` | 清场登出 |
| `GET /api/enterprise/usage?days=` | 用量视图（透传网关计费） |

## 6. 踩坑实录

1. **ENT_SETTINGS_PATH 忘带 = 污染生产**：测试实例启动脚本必须设它（测试实例启动脚本 已内置）。改插件设置页/写 provider 逻辑时先确认目标文件。
2. **改插件代码必须 remove+add 重新同步**：`file:` 安装是复制；只改源码不重装 = 实例跑的还是旧代码。
3. **正则改 settings.yaml 极易翻车**：中文路径 + GBK 控制台 + 复杂补丁——一律写成临时 `.mjs` 脚本用 node 执行，别在 PowerShell 里内联复杂正则（`$` 转义会静默出错）。改完 `node --check` + 单测正则三种状态（块存在/已为空/空行）。
4. **重复 key**：向 YAML 段插入 `providers:` 前先检查已存在，否则产生重复键（DSH 解析行为未定义）。
5. **登出也必须写 llm-deepseek 屏蔽段**：清场路径曾漏掉，导致登出→重登循环后官方 deepseek 模型泄漏进选择器。
6. **心跳在线窗口是 3 分钟**（`ceil(130/60)` 进位），不是字面 130 秒；心跳表时间列存 UTC，查询用 `datetime(ts, '+8 hours')`。
7. **终端聚合分区键 = (device_hash, account)**：同机多实例各按账号独立展示，属正常设计。
8. **UI 不显示模型名**：面板/登录成功消息都不带模型名（企业安全要求，改 UI 时勿加回）。
9. **Desktop 生产实例（43120）**：插件更新后需用户主动重启才生效；未经用户明确要求严禁重启/测试/杀进程。测试一律在 43122。
10. **客户端调 /admin/* 的密钥显示**：面板不展示密钥；`/admin/config` 返回的 `hasKey`/`apiKeyDirect` 是布尔，勿当原文用。
11. **lib/ 是构建产物（v0.5.0 起）**：改 lib 会被下次 `node build.mjs` 覆盖；源码一律在 src-node/ 与 src-client/。发版改版本号要同时改 package.json 与 src-node/shared/version.js。
12. **企业 block-url 规则会扫 Agent 工具参数**：让 Agent 写代码/测试时，若文件内容带完整的被禁域名 URL，**写入动作本身会被规则引擎拦截**（真实发生过：规则自测路由硬编码了外部 AI 站点域名，重构写文件被 cr-ai-1 deny）。自测目标已改为从策略动态取；今后测试代码里构造被禁域名一律用字符串拼接。
13. **本机 Node 22.20 的 cpSync/rmSync 递归会崩（0xC0000409）**：build.mjs 里用手写递归复制/删除，别"优化"回 cpSync。

## 7. 调试速查

| 症状 | 首查 |
| --- | --- |
| 登录成功但模型选择器没有企业模型 | `settings/describe` 是否有 `llm-pi-ai` ns → 校验红线（input 白名单/reasoningEfforts dict） |
| 模型今天有明天消失 | 心跳 modelFingerprint 是否触发 repairConfigure；enterprise-state.json 的快照 |
| 官方 deepseek 混进列表 | settings.yaml 是否有 `llm-deepseek: models: []`（登录+登出两条路径都查） |
| 测试实例改了插件没变化 | 忘了 remove+add 重装插件 |
| 心跳 401 | JWT 过期/被清；看 refresh 续期逻辑与 `.credentials.yaml` |
| 插件写错 settings 文件 | ENT_SETTINGS_PATH 是否与 profile 的 cordis.patch.yml 指向一致 |
